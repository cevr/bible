## Settled

- **Identity in the path, selection and view in the query, time in the hash** (Kitsu, Frame.io, Linear for paths; Figma, Notion for the query; Media Fragments for `#t=`): adopted as the **Addressable** tiebreak in `NORTH_STAR.md`. The scheme to build is ledger row PA-1 (`plans/architecture-loop-2026-10-02.md`): `/films/<film>/{scenes,scenes/<scene>,choices,project,lab/<scene>,play}`, `/sets/<folder>/<point>`, `?cue=|knob=|note=`, `?view=&other=&m=`, `#t=`.
- **The API under `/api/`** (every product above keeps pages and API apart): adopted, ledger row PA-2. A page addressed by film otherwise collides with the API's old per-film paths (the notes sat under the lab's own path); the server dispatches `/api/*` → HttpApi, `/films/<film>/narration/*` → media, built chunks → the build, the rest → the pages.
- **A scenes view that absorbs the look-book** (Resolve Source Tape + Tape View, Storyboard Pro thumbnails, Descript Storyboard View, Frame.io version stacks, FCP keyword bars): adopted, ledger row PA-3. One tape bar across the film with scene boundaries, a grid of scene cards (stills at cue edges, hover or drag scrub, state band, note dots, check count, version badge), a focus panel, phone rows with drag-scrub; `E` opens the lab at the scene and time.
- **Live-drawing every card at once**: rejected on **Performant** (framework): about 25 canvases drawing per frame; cards show cue-edge stills and draw live on one shared canvas only for the card being scrubbed.
- **Time in the path or `?t=`**: rejected on **Addressable**'s tiebreak (path names what, hash names when; `?t=` would make each frame a new resource).
- **Scene-relative time in a scene's lab link** (`/films/<film>/lab/<scene>#t=` counts from the scene's start): adopted with PA-1, so a link survives an earlier scene's re-take; the player keeps film-absolute `#t=`.
- **Values in a JSON store the studio edits** (Theatre.js, Remotion's props editor saving `defaultProps`): rejected on **Lab-first** (framework), as settled in the film loop.
- **One studio shell over a film's places** (Blender workspaces over one shared context; maximize an area and go back): adopted, ledger row PA-7; on a phone one section at a time, full screen, Back to leave. Free-form split and join of areas and layouts saved in a file: rejected (**Mobile-first**, **Addressable**: the link is the layout).
- **Compare modes** (OpenRV wipe, difference, switch; `rvlink://` as the session): wipe and difference for the review's pair (PA-8), difference and hold-to-flip in the lab (PA-9), the compare in the link. Dissolve, add, N-way wipes and session files: rejected (**Mobile-first**, **Comb at a glance**, **Addressable**).
- **Hot reload keeps the place by the URL, not by memory** (Motion Canvas swaps scene modules in place and keeps the frame in localStorage): rejected on **Addressable**; the lab reloads at the URL's place. Adopted from it: the film in the path with an index at `/`, the scene derived from the playhead, timecode display and a flash when new code lands (PA-11).
- **One command registry for keys, `⌘K`, the `?` sheet and buttons** (Motion Canvas `makeShortcuts`, Linear, Rive): adopted, ledger row PA-10; every command also has a touch path.
- **A comment link restores its frame and thread** (Frame.io): confirms PA-4's `?note=`; a note gains an optional scene-relative time (NS-1, additive).
- **Streamed SSR with an SPA after hydration** (Solid 2 `@solidjs/web` rc.11 `renderToStream` + `hydrate`; `05-async-data.md`: `<Loading>` fallbacks flush first, each async value streams as data, `ssrSource: "server"` adopts it with no second fetch, `"hybrid"` continues a live stream, `"client"`/`clientOnly` keep browser-only parts and the scene canvas off the server): adopted as ledger PA-12 (owner pointed at it, 2026-10-02), after the URL and adapter batches. Spike: `pass1/prior-art-solid-ssr.md`. Rejected: `server-functions` and `frames` (**One gate**: a second RPC path beside the HttpApi), the Vite start mode and SolidStart (**One surface**, **Live from source**: a second server and a build step), and a server bundle that imports scene code (**Fresh reads**).
- **What each `ui reduction` source shows at rest, and what waits one step away** (Frame.io player: the picture, one scrub bar, a comment field, with versions, compare, speed, quality, download and status a click away; Linear: one primary action, properties in a quiet column, everything else in `⌘K`, right-click and single keys; iOS: chrome that fades while watching and tools by mode, one at a time; CapCut/Descript: the picture first, one tool tray, a contextual panel for the selection, the timeline collapsed until asked; Blender: panels by context, the sidebar on `N`, every operator in F3): adopted as the shape of every lab view (`pass1/sweep-ui-reduction.md` §2, UR-1..120): a place switcher, the picture, one transport with one rate chip, a mode tray in the lab, one inspector for the selection, and a `⋯`/`⌘K`/`?` trio for the rest. Rejected: hiding the transport in the lab while tweaking (**Mobile-first**: the lab's goal needs the frame step and the scrub at hand), Blender's free sidebar toggling and panels closed by default that hold the view's goal (**Progressive disclosure**: a control used in most visits stays at rest), and Frame.io's per-asset comment field at rest on a list page (**Progressive disclosure**: one comment box for the selection, not one per row).
- **Which of the lab's at-rest controls serve a visit's goal, and which belong behind a sheet, the selection or the command menu**: settled by the inventory (`pass1/sweep-ui-reduction.md` §2): kept at rest are the picture, transport, place switcher, the view's primary verb (pick, approve, record), state badges for exceptions, and in the lab Undo/Redo and the Edit mode's cues and knobs; disclosed are settings (quality, mic, onion, ticks), engine readouts (counts, files, refs, findings, status lines), secondary verbs (reject, unapprove, batch approve, versions, marks) and every per-row comment box, behind a context menu (right-click, long-press), a key, `⌘K`/`?`, a sheet or the selection's inspector, each with a touch path (**Progressive disclosure**, **Mobile-first**). Rejected: removing any of them (**Progressive disclosure**: capability only grows) and replacing a numeric field with a slider (**Progressive disclosure**: precision is capability).
- **Base UI as the base of the primitives, ported to Solid 2** (`mui/base-ui` 1.8, MIT, active): adopted (owner, 2026-10-02) as `@bible/ui` (`packages/ui`), our own port of only the parts the primitives use (ContextMenu with touch long-press, Menu, Drawer as the phone sheet, Toast as the Receipt, NumberField with its scrub area as the inspector's precise field, Popover, Tooltip, Toolbar, ToggleGroup and Tabs for the mode tray, Dialog), keeping Base UI's anatomy, `data-*` attributes, keyboard and ARIA behaviour, over `@floating-ui/dom`. Rejected: the community ports `@msviderok/base-ui-solid` and `@photon-ai/base-ui-solid` as dependencies (Solid 1 peer, betas, ~250 and ~10 weekly downloads; we are on Solid 2 rc.11), read as references for the React → Solid translation only; Kobalte and corvu (Solid 1, another anatomy than the one the owner chose).
- **A mediabunny WebCodecs player for the review's compare** (`vanilagy/mediabunny` `examples/media-player`; frames from `VideoSampleSink` iterators drawn on canvases, one `AudioContext` as the clock; spike `pass1/prior-art-mediabunny-player.md`): adopted as a second adapter behind EA-7's `Playable` port, carried by **p1-scenes** with PA-8, PA-9 and PA-3's scrub, for the synced compare (0–1 frame A–B drift vs `<video>`'s mean 2–5 and up to 64 at 2×), the frame step (11–15 ms forward, exact at frame starts where `<video>` missed 10 in 30), J/K/L, and a key-frame preview while dragging (21–40 frames/s, exact on release). The `Media` service picks it by capability (`VideoDecoder` + `AudioDecoder` or a PCM track + `canDecode`; iOS 26+ qualifies, iOS 16.4–18 is video-only); everything else keeps today's `<video>` driver, which keeps every action (**Mobile-first**: a phone may lose precision, never a capability). Phones default to `<video>` until one iPhone measurement of two 720p proxies (page memory here was 2.5–4× `<video>`'s). Single-video playback and the lab's narration clock stay on `<video>`/`<audio>`. The `Media` service owns the `AudioContext` gesture rule and `navigator.audioSession.type = 'playback'` (the silent switch), mutes off 1×, and queues rapid steps. Rejected: the example's full-size `CanvasSink` (**Performant**, framework: it fell up to 88 frames behind the clock).
- **What an agent-paired DAW teaches the lab** (overdub demo, 2026-10-03; the lab's split is the same: the owner annotates, the agent draws): adopted, each in the batch that owns its primitive. (1) **The selection is the note's scope** (p1-commands, Selection + notes): a note written with a selection carries it as a chip (`scene · cue · t 3.2–4.0 s ×`), cleared with one tap, and a drag across the tape bar or a cue lane selects a time range for it, so the agent reads exactly what the owner meant; the chip prints the same place the PA-1 link does. (2) **Receipts measure before → after** (p1-commands, Receipt): an edit's toast names what moved with both values (`cue slam 0.42 → 0.38 s`, `knob face [960, 800] → [940, 812]`) and carries Undo; an agent's revision of a note answers with the same receipt beside the note. (3) **Acts over the tape bar** (p1-scenes, PA-3): the film's acts (`film.ts` `look`, the chapters) name the ruler above the scene boundaries, and the tape bar has Follow (the view keeps the playhead in sight while playing; off when the owner scrubs away). (4) **A gesture hint for what is selected** (p1-commands, Keymap): the keymap's `when` context prints the gestures and keys for the selection in the inspector's footer, never at rest on the page (**Progressive disclosure**), and on a phone the long-press menu is the hint. Rejected: the three-pane laptop layout at rest (browser, arrangement, agent chat side by side; **Progressive disclosure**, **Mobile-first**: one picture first, the rest one affordance away); suggestion chips and a live agent chat in the lab (**One surface**: notes already reach the agent through `film notes`, and a second chat path beside them splits the record); per-element authorship marks on cues and knobs (no record of who set a value exists, and adding one changes the persisted scene and timings formats: an owner question if wanted; takes already show recorded vs staging).
