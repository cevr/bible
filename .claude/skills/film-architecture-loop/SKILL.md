# Film architecture loop

A **pass** is: coverage audit → review intake → measure → read-only sweeps → triage into batches → per batch: apply in a worktree, one counsel round, merge → live check. Repeat passes until the close rule holds. The vocabulary comes from the `codebase-design` skill; invoke it once at the start, and the `film` skill, whose review loop the live check uses. Read [`north-stars.md`](north-stars.md) before the first sweep: every candidate names the north star it serves.

The ledger is `apps/animations/plans/architecture-loop-<date>.md`: the single source of truth for what is done, rejected and open. Every sweep and apply prompt names it. Pass files (briefs, reports, logs, stills) live in `<scratchpad>/film-pass<N>/`. Decide by the principles in `~/Developer/personal/dotfiles/principles/` and write "decided by <principle>" in the ledger. The loop runs without owner check-ins, except for paid API runs and publishing (see [`rejected.md`](rejected.md)).

## Steps

1. **Open the ledger.** Copy the section layout of the newest `apps/animations/plans/architecture-loop-*.md`, or [`ledger-template.md`](ledger-template.md) when none exists. Record the HEAD hash and the source baseline, the one count every pass uses: `git ls-files ':(glob)apps/animations/**/*.ts' ':(glob)apps/animations/**/*.tsx' ':(glob)packages/film/**/*.ts' ':(glob)packages/film/**/*.tsx' | xargs wc -l | tail -1`. Read [`rejected.md`](rejected.md). Done when the ledger file exists with a baseline.

2. **Coverage audit.** List every framework source directory with its file count (films are not swept until the owner asks for scene review, owner 2026-10-01):
   `git ls-files ':(glob)apps/animations/**/*.ts' ':(glob)apps/animations/**/*.tsx' ':(glob)packages/film/**/*.ts' ':(glob)packages/film/**/*.tsx' ':(exclude)apps/animations/src/films/**' | xargs -n1 dirname | sort | uniq -c`.
   Mark each directory that no earlier ledger names. Those go first. Done when every directory is marked swept-before or unswept.

3. **Review intake.** Gather every open review item from the sources in [`review.md`](review.md) into the ledger's review table, one row each, with where it came from. Review items are a standing batch: a pass never closes with one open. Done when every source is read and every item has a row.

4. **Measure.** Take the performance baseline in [`performance.md`](performance.md) before any sweep reads code. A number that cannot be measured yet (no instrument exists) is itself the first performance finding. Done when the ledger's performance table has every row, measured or marked as a missing instrument.

5. **Prior art, first pass only.** Read [`prior-art.md`](prior-art.md). Survey only what it leaves open (its "to survey" rows); settle each into the list. Done when each new idea is a ledger row: adopt, or rejected with the north star it fails.

6. **Sweep.** Fill [`prompts/sweep.md`](prompts/sweep.md) into `<scratchpad>/film-pass<N>/sweep-brief.md` and launch one read-only agent per area in one message. Areas: engine (`packages/film/src/canvas`), core (`packages/film/src/core`), tools (`packages/film/src/tools`), player and lab (`packages/film/src/player`, the lab server, with [`lab.md`](lab.md)), performance (with [`performance.md`](performance.md) and the baseline), and guardrails (what can `film check`, the `film` and effect lint rules and the types not see). No area sweeps the films (`apps/animations/src/films`): a film is a function of the framework's code, reviewed by the owner in the lab when he asks for scene review. Done when every area has a report, including those with no findings.

7. **Triage.** Group findings and review items into batches by the files they touch. Every report's P3s and "not worth a pass" lines go to the batch that owns their file, whichever area's report holds them; that batch fixes each or rejects it with a reason. Write the pass section of the ledger: verdict, decisions, a triage table (batch, worktree, items) and its `Carried` list (step 10), and commit it. When it is pushed, run `bun run ci --ledger` (step 10): it prints the triage commit `ledger pending`, and the next record carries its line. Done when every finding is in a batch or rejected with a receipt, and every open `Carried` row of the last pass is in a batch or carried on.

8. **Apply.** Each batch gets its own worktree from main: `git worktree add ../bible-tools-p<N>-<batch> -b p<N>-<batch>` (rift cannot clone this repo). Then, in the worktree, `bun install --frozen-lockfile` and link the git-ignored database the cli perf tests read: `ln -s <repo>/packages/core/data/bible.db packages/core/data/bible.db` (without it `test:perf`, in `bun run gate` and CI, fails with `SQLITE_CANTOPEN`); remove the link with the worktree. Launch one apply agent per batch from [`prompts/apply.md`](prompts/apply.md). Batches with disjoint files run in parallel; a batch that needs another's files starts from main after that one merges. At most about eight agents at once. Done per batch when its tree is clean and `bun run gate` passed on its last commit.

9. **Counsel.** One round per batch from [`prompts/counsel.md`](prompts/counsel.md), with the `counsel-review` skill (outside any Workflow: the Codex leg is denied inside one) or a fresh read-only agent. The apply agent fixes each defect with a test that is red first, in one fixup round. Done when every defect has a commit or a written rejection.

10. **Merge.** In the worktree: merge main, resolve there by keeping both sides' edits (never one side's file whole), run `bun run merge-audit`, then `bun run gate > <log> 2>&1; echo "GATE EXIT $?" >> <log>`. `bun run merge-audit [<merge>]` (HEAD by default) redoes git's own merge of the two parents and prints `merge-audit <sha> conflicted=<n> resolved-by-hand=<n>`, then for each file the resolution changed either `keeps both parents' edits` or one line per statement lost: `dropped ^1|^2: "<line>"` (a parent added it; the merge lacks it) or `restored ^1|^2: "<line>"` (a parent removed it; the merge has it again). Then it audits each merge the merged branch made itself (the batch's merges of main, where its conflicts were resolved) the same way, under `merge-audit <sha> inside <merge> …`; the outer merge alone would print `conflicted=0` over them. Each lost statement is put back, or kept out on purpose and named with why on the batch's ledger row. From the repo root: `git merge --no-ff p<N>-<batch>` (bible-tools commits to main; the merge commit names the batch and its items), `bun run merge-audit`, gate into a log, read `GATE EXIT`. Bundle the branch (`git bundle create <scratchpad>/film-pass<N>/p<N>-<batch>.bundle p<N>-<batch>`), then `git worktree remove` it by full path and delete the branch. Write the batch's ledger rows. Each decision the batch's report hands to files it did not own ("decisions for the orchestrator") becomes a row of the pass section's `Carried` list (the decision, the batch it came from, the files), open until a later batch takes it and marks it `done <hash>` or `rejected: <receipt>`; the next pass's sweep brief copies its open rows (`prompts/sweep.md`), and its triage puts each in a batch. Push only when asked. After a push, run `bun run ci --ledger`: it reads every first-parent commit on main after the oldest one the loop's ledgers record, and for each one they have no line for (this push's, or one an earlier record left out), oldest first, waits for that commit's gate run and prints `ci <conclusion> run=<id> sha=<sha> [failed="<job> in <step>: <conclusion> after <n> s (job <n> s; slowest <step> <n> s), …"] <url>` (the parenthesis only for a cancelled job, its slowest step only when that is not the one it stopped in), or `ci none` for a commit pushed inside a later push. Then it prints `ledger missing sha=<sha>` on stderr for each of them, except a last commit that changes only the ledgers (the one that pastes the lines, or a triage), which prints `ledger pending sha=<sha>`: its line goes onto the next record. It exits non-zero unless every run passed and no line is missing. Paste each `ci` line, without its URL, onto the ledger row of the batch its commit belongs to (a merge's line on the batch's row, a ledger commit's on the pass's), commit the ledger, then run `bun run ci --ledger` again. `bun run ci <base>..<head> [--ledger]` reads one stretch of history the same way. A red run is a finding with its run id (`gh run view <id> --log-failed`) and goes to a live-fix batch; it is never re-run to green. Done when the gate on main is green, the rows are written, the worktree is gone, and `bun run ci --ledger` exits 0 (or non-zero only for a red run already on the ledger as a finding).

11. **Live check.** After each merge, or a small group of merges, drive what the batch changed:
    - Films: none is checked, rendered, mixed or reviewed, and no still, clip or montage is made for the owner, until he asks for scene review (owner, 2026-10-01). The batch's diff is the review of what it draws.
    - Lab: `bun run lab <film>` in the background, then drive the changed controls with `agent-browser` (load the `agent-browser` skill); a write-back must leave a clean `git diff` after undo.
    - Performance: rerun the rows in [`performance.md`](performance.md) the batch claimed to move. Note `uptime` before and after; a number taken at a load average over 4 claims neither a regression nor a win.
    - CI: `bun run ci --ledger` prints a line for every commit on main the ledgers lack (`ledger missing sha=…`; a last ledger-only commit `ledger pending`); each missing line goes onto the ledger, a red or cancelled run with a finding. Its `failed=` names the step a job stopped in, and for a cancelled job the job's time and the step that spent the most of it.

    A defect found here becomes a live-fix batch (step 8). Done when the results match intent, the ledger has a live-check row, and every process you started is stopped.

12. **Docs.** Update `apps/animations/README.md`, `packages/film/README.md`, the `film` skill (SKILL, CRAFT and its reference files) and this skill's reference files wherever the pass changed the API, the workflow or a settled decision; add re-proposable rejections to [`rejected.md`](rejected.md). Done when each describes the code as it is.

## Close rule

Close when one pass holds all five: no unswept directory, no open review item, the sweeps report polish only (under about 5 lines of value each), the performance sweep has no measured saving left over its threshold, and the loop reader names no structural change. Then write the report and the final message, ending with the ledger path. A pass that finds a guard blind spot is never the last: close the blind spot, run the guard, and sweep what it reveals.

## What pays late

After pass two, more reading finds little. These found the rest: the coverage audit, guard blind spots, the review intake, and the live check (the lab driven with agent-browser).
