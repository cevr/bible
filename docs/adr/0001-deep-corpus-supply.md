# Keep corpus supply behind one deep operation

External Bible and Writings formats are integrated through one `CorpusSupply.ensure(input?)` operation, where an omitted input is equivalent to `{}` and means Bootstrap. Source decoding, coercion, staging, verification, and activation remain private adapter concerns so every host follows the same policy and cannot assemble a partial installation lifecycle.

Static recipes compose the supported source and destination adapters. A runtime plugin registry was rejected because corpus formats are a maintained product contract, while host-specific storage and transport remain replaceable Effect layers.

Every portable Contribution carries Provenance. Writings stores that identity in the same SQL transaction as its canonical `PublicationArchive`; Bible stages a pinned Artifact, verifies Canon and Study data, commits Provenance, and only then activates it. Browser Activation is owned by one durable generation store that hands readers to the verified candidate before publishing its marker and reconciles registered inactive generations after interruption, while native Activation renames a verified sibling file.
